Smart Security Camera System

Timeline: Jan 2026 – Mar 2026 Core: Computer Vision & Edge AI Deployment: Dockerized Container
Project Overview

An end-to-end intelligent edge surveillance pipeline designed for automated person localization, continuous multi-object tracking across occlusions, deep facial recognition, event persistence in SQLite, and automated Telegram intruder dispatch with live interactive Streamlit and Plotly telemetry.

01

Technology Stack

Python YOLOv8 (Ultralytics) ByteTrack DeepFace FaceNet OpenCV SQLite3 Telegram Bot API Streamlit Plotly Docker
02

Problem Statement & Constraints

!
Unmanageable Passive Video Feeds

Standard security cameras record hundreds of hours of raw footage without real-time classification, leading to missed intrusions and labor-intensive manual auditing.

!
Occlusion & Track Fragmentation

Basic bounding box detectors fail when subjects pass behind obstacles or overlap, leading to frequent ID switching and inaccurate dwell-time measurements.

!
Lack of Instant Alert Channels

Surveillance setups often store logs on local disks with no remote notification pipeline to alert operators immediately upon unauthorized events.

Core Implementation

Detection Engine

Ingests input video streams at native resolutions and runs YOLOv8 inference to filter person-class detections with high confidence thresholds.

Tracking Engine (ByteTrack)

Associates low-confidence and high-confidence bounding boxes between successive frames to retain identity track IDs during motion and partial occlusions.

Face Recognition Subsystem

Crops detected facial regions, computes vector embeddings via FaceNet, and checks Euclidean distance against a local database of known profiles.

Event Logic & Alert Service

Tracks entry time, exit time, and dwell durations; triggers Telegram API HTTP dispatches with image snapshots for unrecognized individuals.

06

Detection & Tracking Pipeline

STAGE 1
Frame Acquisition & Preprocessing OpenCV grabs video frames, corrects color space, and resizes to model input tensors.
STAGE 2
YOLOv8 Spatial Inference Fast feature extraction predicts bounding boxes, confidence scores, and class labels.
STAGE 3
ByteTrack Association Kalman filter state estimation matches detections to existing tracklets without losing track during temporary frame drops.
STAGE 4
Identity Verification & Logging Matches FaceNet embeddings and updates entry/dwell timestamps in SQLite.

Key Engineering Decisions

Why YOLOv8 over older YOLO variants?
YOLOv8 features an anchor-free split-head architecture providing higher mAP and faster inference speed suitable for real-time edge processing.
Why ByteTrack instead of SORT?
ByteTrack preserves low-confidence detection boxes to recover tracks across temporary occlusions, significantly reducing ID switches.
Why SQLite for event persistence?
Zero-configuration, serverless, and lightweight footprint makes SQLite optimal for embedded and single-node surveillance edge boxes.
Why Telegram Bot API for alerts?
Zero infrastructure cost, instant push notifications across mobile and desktop, and native image attachment support.
