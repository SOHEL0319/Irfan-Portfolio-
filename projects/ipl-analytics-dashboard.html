IPL Ball-by-Ball Analytics Dashboard

Time Span: 2008 – 2023 (16 Seasons) Platform: Power BI & DAX Modeling Scope: 200,000+ Ball Records
Project Overview

An interactive business intelligence and sports analytics dashboard built using Power BI and custom DAX calculations. Processed over 200,000 ball-by-ball delivery records across 16 IPL seasons (2008–2023) structured into 4 interactive analysis pages for comprehensive player, team, and match insights.

01

Technology Stack

Power BI Desktop DAX (Data Analysis Expressions) Power Query (M) Star Schema Modeling Python (ETL) Data Sanitization
02

Problem Statement & Constraints

!
High Data Volume & Disjointed Logs

Over 200,000 raw ball entries contained variations in player spelling, franchise rebranding, and fragmented extras that prevented immediate aggregate reporting.

!
Non-Linear Phase Dynamics

Aggregate career strike rates hide crucial situational context such as Powerplay fielding restrictions vs. Death Over pressure performance.

03

Engineering Objectives & System Goals

Relational Star Schema
Design optimized dimension and fact tables to guarantee instant report slicer response times.
Custom DAX Calculations
Develop dynamic measures for strike rates, economy rates, phase averages, and head-to-head records.
Multi-Page Analytical UI
Build 4 clean interactive dashboard views enabling intuitive drill-downs for stakeholders.

4-Page Interactive Dashboard Scope

Page 1: Season Overview

Tournament-level KPIs, champions timeline, boundary counts, total sixes, and venue win percentages.

Page 2: Match-Wise Analytics

Granular match scorecards, innings run progression worm charts, and player of the match highlights.

Page 3: Batting Dynamics

Batter strike rates, boundary distribution, dismissal vulnerability against spin vs. pace, and phase analysis.

Page 4: Bowling Performance

Bowler economy rates, dot-ball ratios, wicket frequency in Powerplay, Middle, and Death overs.

DAX Measure Implementation

STRIKE RATE
Dynamic Strike Rate Measure DIVIDE(SUM(fact_deliveries[batsman_runs]) * 100, COUNTROWS(FILTER(fact_deliveries, fact_deliveries[is_wide] = 0)), 0)
ECONOMY
Bowler Economy Rate Measure DIVIDE(SUM(fact_deliveries[total_runs]) - SUM(fact_deliveries[bye_runs]), [Legal_Overs_Bowled], 0)

Key Engineering Decisions

Why use a Star Schema instead of a single flat table?
Separating fact deliveries from player, team, and match dimension tables reduces memory consumption and enables instantaneous multi-filter cross-slicing.
Why dynamic DAX measures instead of computed columns?
Measures compute at query time based on user filter selections, allowing dynamic re-aggregation across arbitrary date and venue selections without memory bloat.
